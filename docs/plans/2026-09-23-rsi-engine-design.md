# Bug Hunter RSI Engine Design

## 目标

把当前“每日重复运行固定样例”的 Cloudflare Worker，升级为可审计的递归测试策略进化演示：每天根据上一代结果生成不同候选策略，在固定训练集与保留集上比较，只晋级得分更高且回归通过率为 100% 的策略；失败实验也保留，并让设计页读取最新代次、策略、标本和决策。

## 方案

不让系统改写/执行任意源代码，也不依赖模型 API。进化器只在内置的合成目标与封闭测试语法中工作。四个算子为边界扩张、状态序列、并发扰动、输入缩减；当前获胜策略为四算子预算分配权重。每代读取最近七代的算子产出和失败标本，生成五个确定性但随代次变化的候选权重向量。每个候选在固定预算内产生测试输入，并在训练集及独立保留集上评估。

适应度由新缺陷发现、合成分支覆盖、回归通过率和执行成本组成。所有候选都重放已发现标本作为回归集；只要任一回归失败或保留集低于当前冠军，就拒绝晋级。即使候选全部被拒绝，也记录本代、原因、覆盖差距、候选权重和页面修订；新发现的有效标本仍可进入边界库，不因策略未晋级而丢弃。推荐规则采用可版本化的类别规则及证据计数，不在缺乏用户反馈时伪造“修复成功”。

## 数据流与安全边界

Cron 每天唤醒同一纯函数进化引擎；手动“运行进化实验”走相同路径并受节流。Worker 只在 D1 中原子保存运行、候选、晋级结果、策略快照、发现标本和 living-spec 更新。HTML 页面仍是静态资源，通过 `/api/state` 呈现最新状态，不在生产运行时改写或执行页面代码。每日候选数、探测预算、历史窗口均为常量上限；没有文件系统、密钥或真实仓库写权限。

## 验收标准

- 同一代次/日期产生可重现候选；不同代次会改变候选集合。
- 只有回归 100% 且保留集不退步、适应度严格提升的候选可以晋级。
- 无晋级时仍记录失败原因；新缺陷标本、算子权重、建议规则版本和设计修订能被 `/api/state` 读取。
- Cron 与手动实验共用进化逻辑；页面能区分实验代次与样例运行，且明确标示合成基准，不冒称真实仓库分支覆盖。
